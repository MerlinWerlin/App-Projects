# Glaze — build run protocol (cloud)

Glaze is built by the scheduled task "Glaze build" in the cloud, with no PC needed. Each run is a fresh session. All state lives on the **Glaze Build** artifact
https://claude.ai/artifact/6bvEyN2BM16gv3cWidwg8G (canonical value in `ops/ARTIFACT_URL`)
which holds the status page (`index.html`), the repo as a base64 git bundle (`repo.bundle.b64.txt`) and the owner's trial kit as base64 text (`trial-kit.zip.b64.txt`, decoded by the page's Download button).

**Single writer.** This task is the only writer of the repo and the build artifact.
**Two overseers.** The App Factory overseer (Claude) and Codex (OpenAI, on the owner's PC) both review this app every cycle. Their agreed directives and any Codex patches reach this run through the **App Factory Oversight** artifact
https://claude.ai/artifact/Qe59x61ezQ3sbf7Q61FHAu (canonical value in `ops/OVERSIGHT_URL`), which only the overseer writes. This run reads it; it never writes to it.

## Run steps

1. **Restore.** Artifact `read` the build artifact with `path: "repo.bundle.b64.txt"`; note the artifact version shown (the guard). `base64 -d <saved> > /home/claude/glaze.bundle && git clone /home/claude/glaze.bundle /home/claude/glaze && cd /home/claude/glaze && git checkout main`. If the read fails, stop: "Glaze build needs attention: cannot read build artifact".
2. **Lock.** Read `ops/LOCK.json`. If it names another run started under 100 minutes ago with state `running`, stop quietly: "Glaze build: another run is active". (Publishing is guarded by the artifact version, so a simultaneous run loses on publish and must stop without retrying.)
3. **Oversight + owner feedback.**
   a. Artifact `read` the oversight artifact with `path: "oversight.json"`. Take the entry `apps.glaze` (if any): `directives` (agreed by both overseers), `claude_review`, `codex_review`, `patches` (published paths). Read each listed patch with Artifact `read` + `path`, save it under `ops/inbox/`.
   b. Apply directives: add, reorder or reword backlog tasks as directed (new ids continue the sequence), unless a directive breaks a hard rule or the plan's positioning — then reject it with a reason. Review each inbox patch: `git apply --check`, read it, apply if it fits and tests pass, else reject. Record every decision (`date · source · accepted/rejected/partial · why`) in `ops/DECISIONS.md`; move handled patches to `ops/inbox/done/`. Record the oversight version you handled in `ops/status.json` `oversight_seen` so you don't redo it.
   c. Owner feedback: load `ArtifactComments` via ToolSearch if available and list open comments on the build artifact. Each comment from the owner is a request: turn it into a backlog task (or fix it now if small), reply to the comment with what you did or will do, and resolve it once done. Owner requests outrank the backlog order. If the tool is unavailable, skip.
4. **Green check.** If `package.json` exists, try `npm install` (use `npm ci` when a lockfile exists) with a 5-minute timeout.
   - **Registry reachable:** run `npm test` and `npx tsc --noEmit`; fix any red before new work. Commit the lockfile.
   - **Registry unreachable** (DNS/proxy failure — do not try to route around it): run the pure core tests with `node --test "src/core/**/*.test.ts"` (a bare directory argument fails on Node 22; Node strips TypeScript types natively) and typecheck core only (non-test files; tests need `@types/node`, absent offline) with `tsc --ignoreConfig --noEmit --strict --skipLibCheck --target es2022 --module nodenext --moduleResolution nodenext --allowImportingTsExtensions $(ls src/core/*.ts | grep -v '\.test\.ts$')` if `tsc` exists (drop `--ignoreConfig` on tsc < 6). Set `status.json` `typecheck` to `"core only (registry unreachable)"` and add "full install + tsc + expo export needs PC verification" to `next_for_owner` and to the RUNLOG entry. The overseer runs that verification on the PC and reports errors back through directives. Keep UI code conservative (well-known APIs of the listed Expo Go libraries) when it can't be compiled here.
5. **Pick work.** From `ops/backlog.json`, take up to 4 tasks with status `todo` whose deps are all `done`, owner-feedback tasks first, then the ids in `priority_order.order` (if present, in that order), then lowest id. If none are eligible and tasks remain, take the blocker. If everything is `done`, go to step 9.
6. **Build.** Run the tasks as parallel Agent workers (general-purpose, `isolation: "worktree"`, one task each). Give each worker the task JSON, `docs/PLAN.md`, `ops/CONVENTIONS.md`, the result of step 4 (whether npm works), and the rules "own files only, tests + typecheck green (or core-only when the registry is unreachable), commit on your branch" and "Expo Go-compatible libraries only until TRIAL; native modules (T10+) sit behind interfaces with an Expo Go fallback so Expo Go never crashes". With one task, do it yourself.
7. **Integrate.** Merge branches into `main` one at a time; run the suite after each merge. Revert a merge that turns things red and set that task back to `todo` with a note. Mark merged tasks `done` with the commit hash. Add follow-up tasks you discover.
8. **Record.** Append a dated entry to `ops/RUNLOG.md` (tasks, commits, test count, issues, what the overseers asked and what you did). Update `ops/status.json` (tests, typecheck, last_run in Sydney time, headline, next_for_owner, stage). Stage is `build` until every TRIAL milestone task is done, then `trial` (headline "Ready to try on your iPhone"; next_for_owner = the 4 trial steps from docs/TRIAL.md), then `owner-tested` after the owner's first feedback round is fixed, then `release-prep`. Run `python3 ops/render_status.py` to regenerate `index.html`. Never hand-edit `index.html`.
   **Trial kit** (oversight D3-1/D7-1, overseer-sanctioned as in Linework): the artifact refuses `.zip` files, so the kit is published as **`trial-kit.zip.b64.txt`** (base64 text of the zip) and the page's "Download trial kit" button decodes it and saves `glaze-trial-kit.zip` via the downloads capability. After the checkpoint commit in step 10, whenever app code changed since the last published kit (or the last kit came from a red commit): `git archive --format=zip --prefix=glaze/ -o /home/claude/trial-kit.zip HEAD && base64 -w0 /home/claude/trial-kit.zip > /home/claude/trial-kit.zip.b64.txt`, and publish it with the page. Only build the kit from a commit whose full core suite is green. Record the kit's commit in `status.json` `trial_kit_commit`.
9. **Finish line.** When every backlog task is `done`, add the release tasks below if absent and work them in later runs. When those are done too: write `docs/RELEASE_CHECKLIST.md` (owner actions: Apple Developer + Google Play accounts, `eas login`, `eas build -p ios --profile preview`, TestFlight, store listing), set stage `release-prep` and headline "Code complete — ready for TestFlight", then load `list_triggers`/`update_trigger` via ToolSearch, find the scheduled task "Glaze build" and set `enabled: false`. Finish with "Glaze build complete: ..." and the owner's next 3 actions.
   - R1 EAS config (`eas.json` development/preview/production with the native targets from T10–T12), original app icon + splash (glaze drip motif, tokens), bundle id / Android package `com.jared797.glaze` (owner, 16 Oct), `docs/DEVBUILD.md` (how the owner installs a development build once he has an Apple Developer account)
   - R2 Real IAP for Glaze Plus in a dev build (react-native-iap or RevenueCat), one-time only, restore purchases; never gates make-your-own icons, install, or Live Lock Screen with your own video
   - R3 Privacy policy page (`docs/privacy.html`, "Data Not Collected"), support page, App Review notes (`docs/REVIEW_NOTES.md`: no background audio, Live Photo maker, demo video steps, no trademarked icons)
   - R4 Store listing copy for App Store + Play (title, subtitle, keywords, description, 6 screenshot captions) in `docs/STORE.md`; no competitor names; screenshot 1 hook "Themes, icons and widgets that match. One price. No weekly subscription." (24 Oct: no live lock screen promise)
   - R5 End-to-end pass: every screen, every control, permissions denied/allowed, dark mode, accessibility labels, iOS < 26 behaviour for Live Lock Screen; fix gaps
10. **Checkpoint.** Set `ops/LOCK.json` to `{"run": "<ISO time>", "state": "idle"}`. `git add -A && git commit` (footer below), then `sh ops/bundle-check.sh <commit of the last published bundle>` (D215-1: repacks with commit hashes unchanged, writes `/home/claude/out.bundle` and `/home/claude/repo.bundle.b64.txt`, prints the base64 size and any new/changed PNG/JPG over 100 KB; record the size in RUNLOG; above 15.6 MB leave big images out or compress them; never squash history). Publish to the build artifact with `url` = the build artifact URL, `file_path` = the regenerated `index.html`, and `files: {"repo.bundle.b64.txt": "/home/claude/repo.bundle.b64.txt", "trial-kit.zip.b64.txt": "/home/claude/trial-kit.zip.b64.txt"}` (omit the kit entry when it was not rebuilt; files left out are kept). Omit `capabilities` so the page keeps its downloads capability. Every run, including a no-op run, appends a RUNLOG line and checkpoints (oversight D8-1); if it can't, the finish message says why. If the publish is refused because a newer version exists, do not force or retry: report "Glaze build needs attention: version conflict".

Never commit `node_modules`, build output or secrets. Keep the bundle under 10 MB.

## Finish message (every run)
Three lines: tasks done this run (ids) + stage, test count + typecheck, overseer directives/patches handled and what's next. Start with "Glaze build needs attention:" if anything blocks. When the stage first becomes `trial`, start with "Glaze is ready to try on your iPhone:" and give the 4 steps.
