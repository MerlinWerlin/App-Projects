# Designed clocks, batteries and calendars

In **1.0.5**, choose a theme in Glaze, then add Theme Clock, Battery or Calendar from Glaze in the iPhone Home Screen widget picker. Each size uses the chosen theme as soon as its designs reach the shared App Group. The separate **Save to My widget art** action is for existing Seamless widgets with a custom piece. Legacy widget configurations stay registered and iOS places their Home Screen sizes in Other.

`theme.json` keeps the v1 palette and optionally carries the three semantic designs. The theme gallery snapshots and timelines read these designs directly. Existing v1 files can still render from their palette until Glaze refreshes them. The `theme-gallery` simulator scenario adds all three from the system picker, with an option to install over a 1.0.4 app with an existing Home Screen widget.

For **1.0.4**, `widgetIdentityRecipes.ts` assigns each of the 215 themes an outline, illustrated subject and detail, hour marks, hands, battery gauge and calendar treatment. Each analogue clock fills the largest square the family permits. The medium size uses the remaining width for a large time readout. Alpine Starlight's original mountain-and-constellation face is bundled with the app and extension, with live hands centred on the original dial. `assets/widgets/alpine-clock-face.jpg` is a size-optimised copy of the original Alpine clock artwork (source SHA-256 `cfca0ecfdf668928dacfd9dd4eae8707cc9323529ae903aadfb33a7267f17ef5`). Capability 6 upgrades saved designs in place from their existing theme ID and palette, including before the downloaded catalogue loads.

The following delivery record covers the shared layouts in build 31.

Jared's 4 November 2026 correction replaces the generated `themed-live-clock`, `themed-live-date` and `themed-live-battery` editions. Those editions reused decorative pictures with a small value overlaid. Original standalone artwork remains available separately.

Every theme now has three functional designs in Small, Medium and Large. This includes all 141 current catalogue themes, 66 additional bundled entries and eight Space photo themes. The designs use the same palette treatment as the theme's default icons, checked for text contrast. Original vector orbital, botanical, wave, petal, geometric and stitched details stay outside the information area. Subject and material determine dial/digital/split clocks and ring/cell/meter batteries. A calendar is a complete month with the current day highlighted, including six-row months.

`src/core/designedWidgets.ts` defines the semantic document. `DesignedWidget.swift` renders the live WidgetKit composition at the actual widget dimensions. Nothing relies on a small text rectangle or an existing decorative image. The app's SVG preview is `designedWidgetPreview.ts`. Preview battery values come from the device; unavailable readings show a dash. Clock timelines advance by minute, calendars at local midnight, and batteries request periodic refreshes under WidgetKit's normal scheduling.

`live.design` is optional in the existing shared library schema. Capability 5 prevents older binaries from saving designs they cannot render. Stable piece IDs let configured widgets upgrade in place. The deferred startup migration updates existing functional records without changing personal photos, original art, saved selections or creation dates. Theme application adds the nine designs before decorative options. A native helper creates only a tiny backing file to retain existing library/file invariants; the native content renderer uses the semantic design instead of that file. The app library draws a functional thumbnail.

Run the core suite and real app/Node TypeScript checks. `scripts/designed-widget-fixtures.mjs <catalog.json>` regenerates all palette fixtures. `glaze-designed-widgets.yml` compiles actual production WidgetKit sources and renders every palette/function/size plus representative locale, clock, battery and month states. `glaze-native-simulator-app.yml` verifies full Expo/native integration. The `design` scenario of `glaze-native-link-smoke.yml` selects and saves the three designs through the installed app and verifies persisted App Group specs after restart. Simulator proof is distinct from physical-phone testing.
