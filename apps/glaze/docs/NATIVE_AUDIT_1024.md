# Native compile audit, 24 Oct 2026 (T136, oversight D133-2)

One `production-native` TestFlight build has to carry A (widgets follow the theme), B (profile
served to Safari) and C (Live Photo). A Swift compile error costs a whole build, so every Swift file
in `targets/widget`, `modules/glaze-widget-bridge` and `modules/glaze-profile-server` was read line
by line against the Xcode 26 / Swift 6.x toolchain with ExpoModulesCore (SDK 54).

**Nothing here was compiled or run on a device.** There's no Xcode in this environment. The checks
are reading plus Apple / Expo documentation. Source guards for the fixes are in
`src/core/widgetNativeAudit.test.ts`.

## Baseline facts used

- **Language mode.** The widget extension is generated by `@bacons/apple-targets`, which sets
  `SWIFT_VERSION = 5.0` for widget targets (its `configuration-list.ts`). The profile server pod
  sets `swift_version = '5.9'`. The bridge pod sets none, so it inherits Swift 5 from the app.
  Everything compiles in Swift 5 language mode, where Swift 6 concurrency diagnostics (Sendable,
  main-actor access, global mutable statics) are warnings rather than errors.
- **ExpoModulesCore.** `Function` / `AsyncFunction` take up to 8 arguments, including a trailing
  `Promise` (Expo Modules API docs). An AsyncFunction runs off the JS thread and off the main queue
  unless `.runOnQueue(.main)` is used.
- **Known-good baseline.** The 24 Oct native build compiled and installed (RUNLOG run 101, T123/T124
  closed). That build had the habit widgets, App Intents, HabitStore, the Live Lock/Live Photo
  modules and the bridge up to T86. So this audit concentrates on code added since then: T125
  (theme), T126 (profile server) and T131/T133 (Seamless).

## Behaviour checks

- **A (owner brief):** every Home Screen kind and size paints `GlazeBackground(theme:)` or the
  composed image, uses the theme's ink, accent and font choice, and reads the theme in placeholder,
  snapshot and timeline. The fallback is the plum-to-coral default, never white. No view renders
  `theme.name` (T125 guard). The app writes the theme on every apply path and once at launch
  (`src/store/widgetTheme.ts`). The Lock Screen accessory takes only the font, because the system
  tints it.
- **B:** `application/x-apple-aspen-config`, real Safari via `Linking.openURL` (no
  `expo-web-browser`), 90 s timeout plus 20 s grace plus background task, and `stop()` on leaving
  the screen. `PROFILE_INSTALL_ENABLED` still decides whether the profile method shows at all.
  Without the server, Shortcuts is first, recommended and the default (`src/core/installMethods.ts`,
  existing tests).

## Residual risks for the build

- **EAS signing of the extension.** `@bacons/apple-targets` is installed on the build server only
  (`eas-build-post-install`). If `eas build` evaluates the config somewhere the package is missing,
  the App Group and extension credentials may not be synced. The 24 Oct native build signed fine,
  so this is noted, not changed.
