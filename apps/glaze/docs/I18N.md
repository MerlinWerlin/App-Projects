# Languages (i18n)

Glaze follows the phone's language, with an override in **Settings › Language**. It ships English plus
10 translations and a pseudo-locale for testing. No i18n library: a small typed layer on top of `Intl`
and `expo-localization` (ships in Expo Go).

> **Owner action: translation review.** Every non-English catalogue (`src/i18n/locales/*.ts` except
> `en.ts`) is a **machine translation awaiting native-speaker review**. Each file says so in its header,
> and Settings › Language shows a note saying so. Before marketing a language, have a native speaker
> read its file (strings are short and grouped by screen) and fix anything that reads oddly.

## Locales

| Locale    | Language             | Shown as            | Script     | Direction |
|-----------|----------------------|---------------------|------------|-----------|
| `en`      | English (source)     | English             | latin      | LTR       |
| `es`      | Spanish              | Español             | latin      | LTR       |
| `fr`      | French               | Français            | latin      | LTR       |
| `de`      | German               | Deutsch             | latin      | LTR       |
| `it`      | Italian              | Italiano            | latin      | LTR       |
| `pt-BR`   | Portuguese (Brazil)  | Português (Brasil)  | latin      | LTR       |
| `ja`      | Japanese             | 日本語               | cjk        | LTR       |
| `ko`      | Korean               | 한국어               | cjk        | LTR       |
| `zh-Hans` | Simplified Chinese   | 简体中文             | cjk        | LTR       |
| `hi`      | Hindi                | हिन्दी                | devanagari | LTR       |
| `ar`      | Arabic               | العربية              | arabic     | **RTL**   |
| `en-XA`   | Pseudo (dev only)    | Pseudo (testing)    | latin      | LTR       |

Device matching (`resolveLocale` in `src/core/i18n.ts`): the first device language we ship wins, in the
phone's preference order. Any `pt-*` → `pt-BR`; `zh`, `zh-CN`, `zh-SG`, `zh-Hans-*` → `zh-Hans`;
Traditional Chinese (`zh-Hant`, `zh-TW/HK/MO`) is skipped so the next preferred language is used;
regional variants (`en-AU`, `es-MX`, `fr-CA`, `ar-EG`, …) map to their language. Nothing matches → English.

## How it works

| File | Role |
|------|------|
| `src/core/i18n.ts` | Pure TS, tested (`src/core/i18n.test.ts`): locale list and endonyms, `resolveLocale`, `isRTL`, `scriptOf`, `lineHeightScale`, `interpolate`, plurals, `translate`, `pseudoLocalize`, `formatNumber`, `formatDate`, `formatClock`. |
| `src/i18n/locales/en.ts` | The English catalogue (`as const`), source of truth for keys. |
| `src/i18n/locales/<locale>.ts` | One file per language, typed `LocaleMessages` (deep-partial; missing keys fall back to English). |
| `src/i18n/locales/index.ts` | Registers every catalogue (`CATALOGUES`, `TRANSLATIONS`). |
| `src/i18n/catalogue.ts` | Types: `Messages`, `LocaleMessages`, `MessageKey` (valid dotted keys only), `TFunction`. |
| `src/i18n/index.tsx` | React layer: `I18nProvider`, `useT()`, singleton `t()`, override storage, RTL switching. |
| `src/ui/i18nLayout.ts` | `textStyleFor`, `localizedType`, `Chevron`, `flipInRTL`, `noMirror`, `noMirrorText`. |
| `src/ui/LanguageSection.tsx` | Settings › Language row + picker sheet (`LanguagePickerSheet`, also opened from the first-launch line). |
| `src/ui/LanguageHintLine.tsx` | First-launch "Language: English · Change" line on Themes (release standard §1). First session only, gone once tapped; rules in `src/core/languageHint.ts` (tested), flag `glaze.languageHint.v1`. |
| `src/core/i18nCatalogue.test.ts` | Catalogue integrity: no unknown keys, placeholders kept, plural shapes valid, Arabic has all six plural forms, `common`/`tabs`/`settings.language` complete in every locale. |

Lookup order: chosen locale → English → the key itself (so a missing string is visible, never blank).
The override is stored in AsyncStorage under `glaze.locale.v1` (`'system'` or a locale code).
`I18nProvider` (in `app/_layout.tsx`) waits for that one read so the first frame is already translated.

### Using it

```tsx
import { useT } from '../src/i18n';          // in components (re-renders on language change)
const { t, locale, isRTL, script, formatNumber, formatDate, formatClock } = useT();

t('settings.language.title');                               // typed: typos fail to compile
t('settings.language.systemDefaultHint', { language: 'English' });  // params required when {placeholders} exist
t('common.itemCount', { count: 3 });                         // plural: form chosen from count

import { t } from '../src/i18n';               // outside React (toasts, alerts, native payloads)
```

`t` signature: `t<K extends MessageKey>(key: K, ...args: TArgs<K>): string`. Params are required exactly
when the English string has `{placeholders}` (plus `count: number` for plural messages); numbers are
formatted with `Intl.NumberFormat` for the locale before interpolation.

### Adding a string (or a screen's namespace)

1. Add it to `src/i18n/locales/en.ts` under the screen's namespace (`themes`, `icons`, `install`, `live`,
   `theme`, `wallpaper`, `tips`, `feedback`, `addApp`, `ui` for shared components; create a new
   top-level namespace for a new screen). Nest as needed: `install: { steps: { title: '…' } }`.
2. Add the translation to each of the 10 other locale files (same path). Machine translation is fine;
   keep `{placeholders}` exactly. A missing translation falls back to English at runtime, but the
   catalogue test lists namespaces that must be complete: add yours to `COMPLETE_NAMESPACES` in
   `src/core/i18nCatalogue.test.ts` once every locale has it.
3. Use it: `t('install.steps.title')`.

Rules: no string concatenation for sentences (use one message with placeholders, since word order
changes); never use a plural category (`zero one two few many other`) as a key name; keep accessibility
labels and hints in the catalogue too.

### Plurals (ICU-lite)

A leaf can be `{ zero?, one?, two?, few?, many?, other }`. The form comes from `Intl.PluralRules` for the
locale, with a built-in CLDR table for the shipping languages when the engine lacks it (Hermes does not
ship `Intl.PluralRules`). `zero` also acts as an explicit "none" form in any language when `count` is 0.
A missing category falls back to `other`. Arabic needs all six (0 zero, 1 one, 2 two, 3–10 few,
11–99 many, 100+ other per hundred); Japanese, Korean and Chinese only use `other`.

### Pseudo-locale

`en-XA` (Settings › Language › Pseudo (testing), `__DEV__` only) renders English accented, ~40% longer
and wrapped in ⟦ ⟧, with `{placeholders}` intact. Unwrapped text on screen is a hard-coded string;
a missing ⟧ means truncation.

### Widget extension (T86)

The WidgetKit extension can't read the app's catalogue, so it has its own
`targets/widget/<lang>.lproj/Localizable.strings` for the 11 shipping languages (pseudo-locale not
included). It follows the **phone's** language, not the in-app override. Habit widget copy uses
explicit keys (`habit.name.water`, `habit.goalOf` …) through `HabitText` in `HabitStore.swift`;
App Intent titles and other widgets' gallery names use their English literal as the key. Formats
use positional `%1$@ %2$@` so word order can change. To add a string: add it to `en.lproj` and
every sibling file; `src/core/widgetStrings.test.ts` fails on a missing key, a mismatched
argument, or a Swift `String(localized:)` key without an English entry. Same owner action as the
app catalogues: these are machine translations awaiting native-speaker review.

## Layout rules

### Right-to-left (Arabic)

Switching between an LTR and the RTL language calls `I18nManager.allowRTL(true)` +
`I18nManager.forceRTL(rtl)` and then reloads: through the expo-updates native module when present
(looked up with `requireOptionalNativeModule('ExpoUpdates')`, so builds without expo-updates still
bundle and Expo Go never crashes), else `DevSettings.reload()` in development, else the user is told to
close and reopen Glaze. At launch, a direction that drifted (the phone's language changed) is corrected
for the next start without reloading.

**Mirrors** (automatic with `forceRTL` when styles use start/end):
- Use `start`/`end` (`marginStart`, `paddingEnd`, `start: 0`, `borderTopStartRadius`), never left/right,
  for app chrome. Rows, lists, tab order, headers, sheets and the stack push direction mirror.
- Directional icons: `Chevron.forward(isRTL)` / `Chevron.back(isRTL)` / `arrowForward` / `arrowBack`
  give the right Feather name; `flipInRTL(isRTL)` mirrors any other directional glyph. The iOS back
  swipe follows the native direction.

**Never mirrors** (apply `noMirror` = `{ direction: 'ltr' }` to the root view):
- The mock Home Screen and Lock Screen (`HomeMock`, `LockMock`, `PhoneFrame`, already done): iOS keeps
  its own grid, and the preview must match the real phone.
- Artwork, icon previews, wallpapers, theme thumbnails, photos and video crops.
- The Lock Screen clock and numbers: `formatClock(date)` always gives Latin digits, LTR, wrapped in
  U+2066…U+2069 isolates, using the device's 12/24-hour setting; use `noMirrorText` on the Text.

### Text expansion

German and French run ~35% longer. Text wraps instead of truncating: no `numberOfLines={1}` on labels,
`minHeight` (≥ 48 pt) instead of fixed heights, `flexShrink: 1` on text in rows. `Button` already wraps.
Check every screen in the pseudo-locale.

### Scripts and fonts

Unbounded and Manrope cover Latin only. For CJK, Devanagari and Arabic, `textStyleFor(script, base)`
sets `fontFamily: undefined` (system font) and scales line height (CJK ×1.15, Arabic ×1.25,
Devanagari ×1.3); `localizedType(script)` gives the whole `type` scale adapted:
`const tt = localizedType(script); <Text style={[tt.body, …]}>`.

### Dates and numbers

Use `formatNumber(n, options)` / `formatDate(date, options)` from `useT()` (Intl underneath, safe
fallbacks). Pass `{ latinDigits: true }` where digits must stay 0–9. Never build dates from English
month/weekday arrays.

## Build notes (owner / release)

- `expo-localization ~17.0.0` is in `package.json`; run `npx expo install expo-localization` when the
  registry is reachable to refresh the lockfile.
- For TestFlight builds, add the config plugin to `app.json` so iOS lists Glaze's languages in
  Settings › Glaze › Language and enables native RTL:
  `["expo-localization", { "supportsRTL": true }]` and
  `"ios": { "infoPlist": { "CFBundleLocalizations": ["en","es","fr","de","it","pt-BR","ja","ko","zh-Hans","hi","ar"] } }`.
