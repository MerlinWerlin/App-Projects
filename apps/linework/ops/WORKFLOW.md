# Linework — build run protocol (cloud)

Linework is built by the scheduled task "Linework build" in the cloud, with no PC needed. Each run is a fresh session. All state lives on the **Linework Build** artifact
https://claude.ai/artifact/JbSYRfCSnmYQCWnRDZD4qe (canonical value in `ops/ARTIFACT_URL`)
which holds the status page (`index.html`), the repo as a base64 git bundle (`repo.bundle.b64.txt`) and, once T01 is done, the owner's trial kit (`trial-kit.zip`).

**Single writer.** This task is the only writer of the repo and the build artifact.
**Two overseers.** The App Factory overseer (Claude) and Codex (OpenAI, on the owner's PC) both review this app every cycle. Their agreed directives and any Codex patches reach this run through the **App Factory Oversight** artifact
https://claude.ai/artifact/Qe59x61ezQ3sbf7Q61FHAu (canonical value in `ops/OVERSIGHT_URL`), which only the overseer writes. This run reads it; it never writes to it.

## Run steps

1. **Restore.** Artifact `read` the build artifact with `path: "repo.bundle.b64.txt"`; note the artifact version shown (the guard). `base64 -d <saved> > /home/claude/linework.bundle && git clone /home/claude/linework.bundle /home/claude/linework && cd /home/claude/linework && git checkout main`. If the read fails, stop: "Linework build needs attention: cannot read build artifact".
2. **Lock.** Read `ops/LOCK.json`. If it names another run started under 100 minutes ago with state `running`, stop quietly: "Linework build: another run is active". (Publishing is guarded by the artifact version, so a simultaneous run loses on publish and must stop without retrying.)
3. **Oversight + owner feedback.**
   a. Artifact `read` the oversight artifact with `path: "oversight.json"`. Take the entry `apps.tracing` (if any): `directives` (agreed by both overseers), `claude_review`, `codex_review`, `patches` (published paths). Read each listed patch with Artifact `read` + `path`, save it under `ops/inbox/`.
   b. Apply directives: add, reorder or reword backlog tasks as directed (new ids continue the sequence), unless a directive breaks a hard rule or the plan's positioning — then reject it with a reason. Review each inbox patch: `git apply --check`, read it, apply if it fits and tests pass, else reject. Record every decision (`date · source · accepted/rejected/partial · why`) in `ops/DECISIONS.md`; move handled patches to `ops/inbox/done/`. Record the oversight version you handled in `ops/status.json` `oversight_seen` so you don't redo it.
   c. Owner feedback: load `ArtifactComments` via ToolSearch if available and list open comments on the build artifact. Each comment from the owner is a request: turn it into a backlog task (or fix it now if small), reply to the comment with what you did or will do, and resolve it once done. Owner requests outrank the backlog order. If the tool is unavailable, skip.
4. **Green check.** If `package.json` exists, try `npm install` (use `npm ci` when a lockfile exists) with a 5-minute timeout.
   - **Registry reachable:** run `npm test` and `npx tsc --noEmit`; fix any red before new work. Commit the lockfile.
   - **Registry unreachable** (DNS/proxy failure — do not try to route around it): run the pure tests with `npm test` (plain `node --test` with globs; Node strips TypeScript types natively) and typecheck core only with `sh ops/typecheck-core.sh` (strict nodenext tsc of src/core + src/i18n) if `tsc` exists. Also run `npm run typecheck:ui` (offline strict tsc of app/ + src/ against `scripts/tsc-stubs/`) alongside `node ops/ui-check.mjs` here and at every checkpoint (step 10); fix real errors, and have the RUNLOG entry list any errors judged stub-only (see `scripts/tsc-stubs/README.md`). Set `status.json` `typecheck` to `"core only (registry unreachable)"` and add "full install + tsc + expo export needs PC verification" to `next_for_owner` and to the RUNLOG entry. The overseer runs that verification on the PC and reports errors back through directives. Keep UI code conservative (well-known APIs of the listed Expo Go libraries) when it can't be compiled here.
   **Idle-run safeguard (D91-1):** if steps 3 and 5 leave no work for this run (no new directives, patches or owner comments, and a freeze or no eligible task), append the one-line RUNLOG entry and checkpoint (step 10, with the trial kit) immediately after this green check, before any optional reading, so every run leaves a trace.
5. **Pick work.** From `ops/backlog.json`, take up to 4 tasks with status `todo` whose deps are all `done`, owner-feedback tasks first, then lowest id. If none are eligible and tasks remain, take the blocker. If everything is `done`, go to step 9.
6. **Build.** Run the tasks as parallel Agent workers (general-purpose, `isolation: "worktree"`, one task each). Give each worker the task JSON, `docs/PLAN.md`, `ops/CONVENTIONS.md`, the result of step 4 (whether npm works), and the rules "own files only, tests + typecheck green (or core-only when the registry is unreachable), commit on your branch" and "Expo Go-compatible libraries only until TRIAL". With one task, do it yourself.
7. **Integrate.** Merge branches into `main` one at a time; run the suite after each merge — `npm test`, `sh ops/typecheck-core.sh`, `npm run typecheck:ui` and `node ops/ui-check.mjs` (D75-1: no checkpoint publishes with UI type errors; when a task uses a new expo/react-native API, extend `scripts/tsc-stubs/` in the same commit). Revert a merge that turns things red and set that task back to `todo` with a note. Mark merged tasks `done` with the commit hash. Add follow-up tasks you discover.
8. **Record.** Append a dated entry to `ops/RUNLOG.md` (tasks, commits, test count, issues, what the overseers asked and what you did). Update `ops/status.json` (tests, typecheck, last_run in Sydney time, headline, next_for_owner, stage). Stage is `build` until every TRIAL milestone task is done, then `trial` (headline "Ready to try on your iPhone"; next_for_owner = the 4 trial steps from docs/TRIAL.md), then `owner-tested` after the owner's first feedback round is fixed, then `release-prep`. Run `python3 ops/render_status.py` to regenerate `index.html`. Never hand-edit `index.html`.
   **Trial kit** (once T01 is done, every run): after the checkpoint commit in step 10, `git archive --format=zip --prefix=linework/ -o /home/claude/trial-kit.zip HEAD && base64 -w0 /home/claude/trial-kit.zip > /home/claude/trial-kit.zip.b64.txt`, and publish the .b64.txt with the page (the artifact host refuses .zip files; the page's Download button decodes it back into `linework-trial-kit.zip` in the browser). Keep `status.json` `trial_kit: true`.
9. **Finish line.** When every backlog task is `done`, add the release tasks below if absent and work them in later runs. When those are done too: write `docs/RELEASE_CHECKLIST.md` (owner actions: Apple Developer + Google Play accounts, `eas login`, `eas build -p ios --profile preview`, TestFlight, store listing), set stage `release-prep` and headline "Code complete — ready for TestFlight", then load `list_triggers`/`update_trigger` via ToolSearch, find the scheduled task "Linework build" and set `enabled: false`. Finish with "Linework build complete: ..." and the owner's next 3 actions.
   - R1 EAS config (`eas.json` development/preview/production), original app icon + splash (pencil line motif, tokens), placeholder bundle ids `app.linework.ios` / `app.linework.android`
   - R2 Real IAP for Linework Plus in a dev build (react-native-iap or RevenueCat), still never gating tracing; restore purchases
   - R3 Privacy policy page (`docs/privacy.html`, "Data Not Collected"), support page
   - R4 Store listing copy for App Store + Play (title, subtitle, keywords, description, 6 screenshot captions) in `docs/STORE.md`; no competitor names
   - R5 End-to-end pass: every screen, every control, permissions denied/allowed, dark mode, accessibility labels; fix gaps
10. **Checkpoint.** Set `ops/LOCK.json` to `{"run": "<ISO time>", "state": "idle"}`. `git add -A && git commit` (footer below), `git bundle create /home/claude/out.bundle --all`, `base64 -w0 /home/claude/out.bundle > /home/claude/repo.bundle.b64.txt`. Publish to the build artifact with `url` = the build artifact URL, `file_path` = the regenerated `index.html`, and `files: {"repo.bundle.b64.txt": "/home/claude/repo.bundle.b64.txt", "trial-kit.zip.b64.txt": "/home/claude/trial-kit.zip.b64.txt"}` (omit the kit before T01 is done; if it is refused, publish without it and note it). If the publish is refused because a newer version exists, do not force or retry: report "Linework build needs attention: version conflict".

Never commit `node_modules`, build output or secrets. Keep the bundle under 10 MB.

## Finish message (every run)
Three lines: tasks done this run (ids) + stage, test count + typecheck, overseer directives/patches handled and what's next. Start with "Linework build needs attention:" if anything blocks. When the stage first becomes `trial`, start with "Linework is ready to try on your iPhone:" and give the 4 steps.
