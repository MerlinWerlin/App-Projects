# Languages and adaptive layout

Owner request 16 Oct 2026 (R3, `docs/OWNER_1016.md`). Linework follows the phone's language, with an override in
Settings → Language. This page says how the language layer works and the rules every screen follows.

**Every language except English is a machine translation that has not yet been checked by a native speaker.**
Settings shows this too (`settings.language.machineNote`). Before a store launch in a language, have a native
speaker read the whole catalogue in the app.

The phone's languages are matched in order: an exact match first, then the same language (`pt-PT` → `pt-BR`,
`zh-Hant` → `zh-Hans`, `es-MX` → `es`), otherwise English (`resolveLocale` in `src/i18n/core.ts`).

## Adding a string

1. Pick the area file in `src/i18n/en/` for the screen (shared buttons go in `common.ts`). Keys start with the
   area name: `'trace.lock'`, `'prepare.detail.hint'`.
2. Add the English text. Keys are typed: `t('trace.lokc')` is a compile error.
3. Placeholders are `{name}`: `'trace.zoom': 'Zoom {percent}'` → `t('trace.zoom', { percent: percent(0.5) })`.
   Numbers passed as params are formatted for the locale automatically.
4. Plurals use an object with Intl plural categories; pass `count`:
   `'home.recent': { one: '{count} photo', other: '{count} photos' }` → `t('home.recent', { count: n })`.
   Never build plurals or sentences by joining pieces (`n + ' photo' + (n > 1 ? 's' : '')`): word order differs
   between languages. Write the whole sentence with placeholders.
5. Add the same key to every file in `src/i18n/locales/` (`src/i18n/catalogs.test.ts` fails if a key or a
   placeholder is missing). Until a translator has done it, English is shown as the fallback.
6. In screens: `const { t } = useT();` (re-renders on language change). Outside React (toasts, alerts in helpers):
   `import { t } from '../src/i18n'`. For keys built at runtime use `tDynamic(key, fallback)`.

Accessibility labels, hints, `accessibilityActions` labels, `Alert.alert` text, `announceForAccessibility` text and
toasts are user-facing too: they all go through `t()`.

## Adding a language

1. Add it to `LOCALES` in `src/i18n/core.ts` (code, native name, English name, `dir`, `script`) and to the
   `LocaleCode` type.
2. Create `src/i18n/locales/<code>.ts` with every English key (copy a finished locale as the template) and register
   it in `src/i18n/catalogs.ts`.
3. If it uses a script we do not have yet, add it to `Script` and give it a `lineHeightScale`.
4. Add the row to the table above, marked "machine translation, awaiting native review" until reviewed.
5. Run `npm test` (catalogue parity, placeholders, pseudo-locale, scanners).

## Right-to-left (Arabic)

React Native mirrors the whole layout when `I18nManager.isRTL` is true: rows run right to left, `start`/`end`
swap sides, and the back swipe comes from the right. The direction can only change after a reload, so:

- **Switching language in Settings:** call `setLanguage(code)` then `applyLayoutDirection()`. It sets
  `I18nManager.allowRTL` / `forceRTL` and reloads the app (`expo-updates` `reloadAsync()` when updates are enabled,
  the development reload in Expo Go), returning `'reloading'`. If it cannot reload it returns `'restart-needed'`:
  show `settings.language.restartManual`. `'unchanged'` means nothing to do. A reload that does not stick is
  never retried in a loop.
- **At launch:** the root layout calls `startupDirectionCheck()` right after `await initI18n()`. That covers the
  first launch on an Arabic phone and a language changed while the app was closed.

Rules for screens:

- Use `marginStart`/`marginEnd`, `paddingStart`/`paddingEnd`, `start`/`end`, `borderStartWidth` etc. — never
  `marginLeft`/`Right`, `left:`/`right:` or `textAlign: 'left'|'right'` (use `'auto'`, or leave it out). Symmetric
  pairs (`left: 0, right: 0`) and `hitSlop` are fine.
- Chevrons and arrows that mean "forward" or "back" use `forwardChevron()` / `backChevron()` (and
  `forwardArrow()` / `backArrow()`), never a fixed `'chevron-right'`.
- Anything else that depends on side (an animation sliding in from the start, a swipe direction):
  `swapIfRTL(ltrValue, rtlValue)`.

**Never mirrored:** the camera preview, the traced image and its outline overlay, the compare view (your paper vs
the reference), the grid and the lightbox image. A photo must not flip because the language is Arabic, and the
pan/pinch/rotate maths works in screen coordinates. Wrap that stack in a view with `style={NEVER_MIRROR}` (which is
`{ direction: 'ltr' }`) and mark the physical left/right inside with `// rtl-physical-ok` (one line or one style
object) or `// rtl-physical-ok:begin` … `// rtl-physical-ok:end` (a region). The buttons floating on top of the
camera are outside that wrapper and do mirror.

**Numbers stay left-to-right:** percentages, timers, sizes and counts are wrapped in Unicode left-to-right isolates
by `formatPercent`, `formatDuration` and `formatUnit` (and `ltr(text)` for anything custom), so "٤٢٪" or "1:05"
never reorders inside Arabic text. Use the formatters from `useT()` (`percent`, `duration`, `num`, `date`) instead
of `` `${n}%` ``.

## Text expansion

German and French run about 35% longer than English, and some words do not break. So:

- Text wraps. Do not put `numberOfLines={1}` on labels, buttons or captions (use it only for things like file
  names, with `// expansion-ok`).
- Buttons, chips and rows use `minHeight` (≥ 48, the touch target), never a fixed `height`, and grow with their
  text. Rows with an icon and a label use `flexShrink: 1` on the label.
- Leave room: avoid fixed widths on anything holding text; prefer `flexWrap: 'wrap'` for chip rows.
- Check new screens with the pseudo-locale (below) and in German.

## Script typography

Fraunces and Inter only cover Latin. For Japanese, Korean, Chinese, Hindi and Arabic the system font is used
(it has the glyphs and correct metrics), and lines get taller so marks above and below the letters are not
clipped: line height = round(font size × 1.45 × scale), where scale is 1 for Latin, 1.15 for CJK, 1.3 for
Devanagari and 1.25 for Arabic (`lineHeightScale` in `core.ts`). Display headings use ratio 1.2.

In screens:

```tsx
const ty = useTypography();            // or: const { c, typo: ty } = useTheme();
<Text style={[styles.title, ty.font('display', 28, DISPLAY_LINE_RATIO)]}>{t('home.title')}</Text>
<Text style={{ fontFamily: ty.family('body'), fontSize: 16, lineHeight: ty.lh(16) }}>{t('home.body')}</Text>
```

- `ty.family(kind)` → the brand font for Latin, `undefined` (system font) otherwise.
- `ty.weight(kind)` → a `fontWeight` to pair with the system font (the brand family names carry their weight).
- `ty.lh(size, ratio?)` → the line height for the current script.
- `ty.font(kind, size, ratio?)` → all four as one style, to put after a StyleSheet style.
- `ty.face(kind)` → just `{ fontFamily }` (Latin, identical to `fonts.*`) or `{ fontFamily: undefined, fontWeight }`;
  spread it where a style used `fontFamily: fonts.x`. This is what app/ and src/ui/ use (T43).
- `ty.lhOf(latinLineHeight)` → a line height a screen fixed for Latin with its own ratio (e.g. 15 → 21), scaled for
  the script; Latin returns it unchanged, so Latin layout stays pixel-identical.

Module-level StyleSheets that use `fonts.*` keep working; add `ty.font(...)` after them where text is translated.
Never set a fixed `lineHeight` smaller than `ty.lh(size)`.

## Dates, numbers and units

Use the `useT()` formatters, which use `Intl` for the current language: `num(n)`, `percent(fraction)`,
`date(d, opts)`, `duration(seconds)`; and `formatUnit(n, 'centimeter', locale)` from `core.ts`. Never format by
hand (`toFixed`, `${n}%`, month names): decimal separators, percent spacing ("50 %" in French) and digits (Arabic
uses Arabic-Indic digits) differ.

## Pseudo-locale

The language setting value `'pseudo'` (store `LanguageSetting`) shows every English string accented and about 40%
longer, in brackets: "Lock image" → "[Ļóçķ íɱáĝé ~~~~]". Placeholders are kept. It is meant only as a developer option in
Settings → Language (development builds) for layout testing: anything cut off, overlapping or not bracketed (a hard-coded string) shows
up at once. It is never offered to normal users.

## Scanner tests

`src/i18n/scan.test.ts` (part of `npm test`) scans `app/**/*.tsx` and `src/ui/**` with the pure scanners in
`src/i18n/scan.ts`:

| Check | What it finds | Escape hatch |
|---|---|---|
| a | Hard-coded UI text: JSX text, string `accessibilityLabel` / `accessibilityHint` / `placeholder` / `title` / `label` / `caption` / `body` … props, `label: '…'` / `text: '…'` objects (accessibilityActions, Alert buttons, options), `Alert.alert('…')`, `announceForAccessibility('…')`, `toast/show('…')`. Symbols, `%` and `×` are fine. | `// i18n-ignore` on the line |
| b | `marginLeft/Right`, `paddingLeft/Right`, `borderLeft*/Right*`, `left:`/`right:`, `textAlign: 'left'/'right'` | `// rtl-physical-ok` (line or style block), `:begin`/`:end` regions |
| c | Main screens (`index`, `templates`, `prepare`, `trace`, `lightbox`, `settings`): fixed chevron/arrow icon names; `prepare`, `trace` and `lightbox` must contain a `NEVER_MIRROR` / `direction: 'ltr'` wrapper | `// rtl-physical-ok` |
| d | Every English message's pseudo text is ≥ 1.4× longer with the same placeholders (always enforced); `numberOfLines={1}` and fixed-height pressables with text on the main screens (diagnostic only) | `// expansion-ok` |
| e | `formatPercent` / `formatDuration` / `formatUnit` output is LTR-isolated in every locale, Arabic included (always enforced) | — |

`const ENFORCE = false;` at the top of the test file: the checks run and print their findings as test diagnostics
but do not fail. Flip it to `true` (or one entry of `ENFORCE_CHECK`) once the string and start/end migration has
merged; from then on a hard-coded string or a `marginLeft` fails `npm test`. `SCAN_VERBOSE=1 npm test` lists every
finding. The scanner is a small lexer, not a full parser; if it misreads something, add a fixture to the self-tests
in `scan.test.ts` and fix `scan.ts` rather than sprinkling ignore comments.

## Hermes and Intl (fb-1017 F1)
Hermes (Expo Go and release builds) has Intl.NumberFormat, DateTimeFormat and Collator but **no** PluralRules, RelativeTimeFormat, ListFormat, Segmenter or DisplayNames. `new Intl.PluralRules()` crashed the Templates screen and photo picking on the owner's iPhone (17 Oct). Audit of every Intl use:
- `pluralCategory` (src/i18n/core.ts): feature-detects the constructor, falls back to a CLDR table (`fallbackRule`) for all 11 languages; tested with Intl.PluralRules deleted.
- `formatNumber`, `formatPercent`, `formatDate`, `formatUnit`, `formatDuration`: NumberFormat / DateTimeFormat inside try/catch with plain-text fallbacks (unit style may be missing on some engines → "25 centimeter").
- `src/i18n/index.tsx` phone-language fallback: `Intl.DateTimeFormat().resolvedOptions()` inside try/catch.
- No other Intl, toLocale* or localeCompare calls in app/ or src/.
Rule: `ops/ui-check.mjs` and `src/i18n/hermesIntl.test.ts` fail on any direct use of the five missing APIs outside guarded helpers.
