# Languages (i18n) and right-to-left layout

Couch follows the phone's language, with an override in **Settings → Language**. English is the
source of truth; every other catalogue is a machine translation that still needs a native speaker.

## Where things live

| File | What |
|---|---|
| `src/i18n/locales.ts` | The 11 locales (`LOCALES`): native/English names, direction, script, BCP-47 tag. `resolveLocale()` maps the phone's languages to a shipped one (`pt-PT` → `pt-BR`, `zh-Hant` → `zh-Hans`, unknown → `en`). |
| `src/i18n/catalog/en/{core,ui,app}.ts` | English messages, split by where the text is used: `core.*` (src/core), `ui.*` (src/ui, src/state), `app.*` (screens under app/). |
| `src/i18n/catalog/<code>.ts` | One catalogue per other language. `Partial`: a missing key falls back to English, never to the raw key. |
| `src/i18n/core.ts` | `t()`, `setLocale()`, plurals, `formatNumber()`, `formatDate()`, pseudo-locale. Pure TS. |
| `src/i18n/react.ts` | `useT()` and `useLocale()`: components re-render when the language changes. |
| `src/i18n/direction.ts` | Whether a language change needs a restart to flip the layout. |
| `src/native/rtl.ts` | `applyDirection()` (forceRTL + reload), `syncDirectionOnStart()` (forceRTL, no reload). |
| `src/native/localization.ts` | Phone language tags via expo-localization (guarded). |
| `src/ui/settings/LanguagePicker.tsx` | The Settings row. |
| `src/ui/Text.tsx` | Drop-in `Text` with per-script typography. |
| `src/ui/NeverMirror.tsx` | Keeps physical left/right for remote controls. |
| `src/i18n/scan.ts` | Scanners used by tests: hard-coded strings, physical left/right styles. |

## Keys

Keys are `<layer>.<area>.<name>`, e.g. `app.settings.title`, `ui.remote.power`,
`core.settings.language.title`. They are typed from the English catalogue, so a typo is a compile
error. Name keys by meaning, not by wording (`restartNow`, not `restartNowButtonText`).

## Using it

```tsx
import { useT } from '../src/i18n/react';
import { Text } from '../src/ui/Text';

const t = useT();
<Text>{t('app.settings.title')}</Text>
<Pressable accessibilityLabel={t('ui.remote.power')} />
```

Outside React (pure TS, alerts built from a callback): `import { t } from 'src/i18n/core'`.
`t(key, params, locale)` takes an explicit locale when needed, e.g. the language picker asks its
restart question in the language just chosen.

- **Placeholders:** `'Code {n} of {total}'` → `t(key, { n: 2, total: 9 })`. Numbers are formatted for
  the locale (`1.200` in German). Every translation must keep exactly the English placeholders.
- **Plurals:** a message can be `{ one: '{count} TV', other: '{count} TVs' }`; the form is chosen with
  `Intl.PluralRules` for the active language (Arabic uses `zero/one/two/few/many/other`, Japanese only
  `other`). `other` is required; `zero`, when present, wins for 0. Pass `{ count }`.
- **Never** build sentences by concatenating translated fragments; word order differs. Make one
  message with placeholders.
- **Numbers and dates:** `formatNumber(n)`, `formatDate(d)` (Intl with the locale's BCP-47 tag).

## Driver errors (user-facing vs diagnostic)

TV drivers (`src/core/drivers/**`) throw `DriverError(code, message)`. The **code** is for logic and
stays stable; never branch on the message. The **message** reaches the user (toasts via
`describeError()` in `src/core/session.ts`, the driver's `error` event, the add-TV and pairing
screens), so it is always a catalogue key translated when thrown:

```ts
import { driverError, asDriverError } from './errors';
throw driverError('unsupported', 'core.driver.firetv.vegaOs');
throw driverError('network', 'core.driver.common.deviceHttp', { device: 'Roku', status: String(res.status) });
const err = asDriverError(e); // unknown error -> 'network', translated, raw text kept as {detail}
```

- Keys: `core.driver.common.*` for messages shared by drivers, `core.driver.<driver>.*` otherwise
  (`samsung`, `webos`, `androidtv`, `firetv`, `roku`, `sony`, `philips`, `vizio`, `ir`, `demo`).
- Brand / product names are data in `{device}` (`'Roku'`, `'Fire TV'`, `'Sony TV'`), not translated.
- Technical values (key names, app ids, HTTP status, ports, raw TV replies) are passed as strings so
  they are not number-formatted (`port 8002`, not `8,002`).
- **Diagnostic-only** text that never reaches users may stay English: code comments, programming
  errors (`'no emitter'`), and the raw text of an unexpected error, which only appears inside the
  translated `core.driver.common.unexpected` as `{detail}`.
- The IR brand grid uses `irBrandChoiceLabel()` (`src/core/ir/codes.ts`): brands are data,
  "Not sure" is `core.ir.notSure`.
- `tests/i18n-driver-errors.test.ts` fails on any `new DriverError(code, 'literal')` or literal
  `error` event in the drivers, and checks pseudo-localised driver toasts.

## Pseudo-locale

`t(key, params, 'pseudo')` returns accented English about 40% longer, in brackets:
`Settings` → `[Šéţţíñĝš ~ ~]`. It shows truncation (text must wrap, buttons must grow) and any
text that did not go through `t()`. It is never offered in Settings.

## Adding a language

1. Add it to `LOCALES` in `src/i18n/locales.ts` (code, native name, English name, `dir`, `script`,
   BCP-47 tag) and to `LanguagePref` / `LANGUAGE_PREFS` in `src/core/prefs.ts`.
2. Create `src/i18n/catalog/<code>.ts` exporting a `Catalogue` and register it in
   `src/i18n/catalog/index.ts`.
3. If `resolveLocale()` needs a special case (regional variants), add it with a test.
4. Add a row to the table above with status "Machine translation — awaiting native review" until a
   native speaker signs off.
5. `bun test` / `npm test`: `tests/i18n-catalogues.test.ts` checks unknown keys, placeholders and
   plural `other`, and reports missing keys.

## Tests that guard this

- `src/i18n/i18n.test.ts`: t(), plurals, number formatting, locale resolution.
- `tests/i18n-catalogues.test.ts`: every catalogue key exists in English with the same placeholders;
  plurals have `other`; missing keys are reported (strict once the translations land); the
  pseudo-locale grows every English message by at least 30% and keeps parameter values.
- `src/i18n/scan.ts` + `scan.test.ts`: `findHardcodedStrings()` (JSX text, `accessibilityLabel` /
  `accessibilityHint` / `placeholder` / `title` props, `title:` / `tabBarLabel:` / `headerTitle:`
  options, `Alert.alert` literals), `findPhysicalDirections()`, `usesNeverMirror()`. Glyphs such as
  `›`, `+`, `−`, `•` and numbers are not reported. Add `// i18n-ignore` (or `{/* i18n-ignore */}`) on a
  line to exempt it, e.g. the brand name.
- `src/i18n/direction.test.ts`, `tests/rtl.test.ts`: when a restart is needed; forceRTL / reload.

## Right-to-left (Arabic)

React Native fixes the layout direction when the app starts. `I18nManager.forceRTL()` only takes
effect after a reload, so:

- Switching between two left-to-right languages is instant.
- Switching to or from Arabic shows a confirmation ("Restart Couch?", in the chosen language). **Restart
  now** calls `applyDirection()`: `allowRTL(true)`, `forceRTL(...)`, `swapLeftAndRightInRTL(true)`, then
  reloads (expo-updates `reloadAsync`, else `DevSettings.reload`). **Later** stores the direction for
  the next launch.
- At app start `syncDirectionOnStart(locale)` writes the direction for the resolved language without
  reloading (it applies on the next launch), so a phone switched to Arabic is right-to-left from the
  second start at the latest.

### Layout rules

- Use `start` / `end` styles: `marginStart`, `paddingEnd`, `start: 0`, `borderStartWidth`,
  `textAlign: 'auto'`. Do not use `marginLeft`, `paddingRight`, `left:`, `right:`,
  `borderLeftWidth`, `textAlign: 'left' | 'right'` (the scanner reports these).
- Direction-meaning glyphs (chevrons `›`, back arrows) flip in RTL: `transform: [{ scaleX: I18nManager.isRTL ? -1 : 1 }]`.
  Back gestures follow the navigator's direction automatically.
- Text wraps rather than truncates; avoid `numberOfLines={1}` on translated copy, and let buttons grow.

### Never mirror

These controls map to the TV's **physical** directions and keep left on the left in every language.
Wrap them in `<NeverMirror>` (`src/ui/NeverMirror.tsx`, sets `direction: 'ltr'`):

- the d-pad (up / down / left / right / OK);
- arrow keys and any left/right key rows;
- volume and channel rockers;
- rewind / fast-forward (and previous / next track);
- the touchpad (swipe left means left on the TV).

Labels inside them are still translated; only the layout is not mirrored.

## Script typography

Use `Text` from `src/ui/Text.tsx`, not react-native's. For CJK, Devanagari and Arabic it swaps the
brand fonts (Sora / Manrope, Latin only) for the system font at the same weight and uses taller line
heights (`src/theme/typography.ts`: Latin 1.3, CJK 1.45, Devanagari and Arabic 1.6). Latin text is
unchanged.

## Voice

Hold-to-talk speech recognition uses the selected app language (`voiceLanguage()` in
`src/core/voice.ts`: the locale's BCP-47 tag, e.g. `fr-FR`, passed to `SpeechToText.start`). Expo Go
has no speech module and keeps the keyboard fallback.
