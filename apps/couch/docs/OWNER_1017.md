## F. Remote themes + store screenshots (owner-1017)

The owner wants the remote itself to come in distinct themes that also make striking App Store / Play Store screenshots. Tasks rank right after the owner-1016 release tasks R1–R2 (done).

- **T1 Theme system** (backlog T56): a typed theme token set (surface, key face, key edge/bevel, key text, d-pad ring, accent, glow colour for the "cinema glow", haptic/press style, corner radius, optional texture) in `src/theme/remoteThemes.ts`; every remote control, sheet and the glow read it; a Themes screen in Settings with a live preview of the remote and instant apply (spring cross-fade), remembered per device; works in Expo Go; respects Reduce Motion and keeps WCAG AA contrast on every key label (test it). Themes never change what a button does and never hide a control.
- **T2 At least 10 original themes** (T57) with clear personalities, e.g. Midnight (default, deep navy glass), Daylight (light, soft paper), OLED Black, Cinema Red (velvet + warm glow), Brushed Aluminium, Retro Wood (1980s woodgrain + cream keys), Neon Arcade (dark with pink/cyan edge light), Pastel Candy, Forest (deep green + brass), Aurora (animated gradient glow, paused when idle). Textures are generated (SVG/gradients/noise), never photos or anyone else's artwork. 3 are free (Midnight, Daylight, OLED Black); the rest are Couch Plus (one-time purchase, never a subscription), with a "Try it" preview that works without buying. Every TV control stays free in every theme.
- **T3 Mirror the themes into `prototype/index.html`** (T58) with a theme switcher in the demo so the same looks render in a plain browser.
- **T4 Store screenshot kit** (T59): `store/render.mjs` uses Playwright with the preinstalled Chromium (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`; never run `playwright install`) to render the prototype in the demo TV state into App Store sizes 1320x2868 (iPhone 6.9") and 1242x2688 (6.5"), plus Play Store 1080x1920, as framed marketing images: device frame drawn in SVG, a short benefit headline above (e.g. "Every TV. No subscription for the buttons.", "Make it yours: 10 themes", "Find your TV in seconds", "Talk to search"), one theme per shot, consistent typography, an English set first with the headline strings in the i18n catalogue so other languages can be rendered later. Output to `store/screenshots/<size>/NN-name.png` and a contact sheet `store/screenshots/index.html`. Publish the PNGs on the build artifact as extra files (keep total under the artifact size limit; JPEG previews in the contact sheet if needed; per D62-1 only the 6.9" set in full if space is tight) and link them from the status page under "Store screenshots". ## G. OK button (fb-1017-ok)

The owner said the centre OK button of the d-pad looked off when he last tried the app on his iPhone in Expo Go. The OK key is a true circle exactly centred in the d-pad ring with an equal gap all round (one size variable shared by ring and key, never hard-coded offsets), about 38–42% of the ring's diameter and never clipped; the "OK" label is optically centred (lineHeight equal to fontSize, no baseline offset, includeFontPadding false on Android, textAlignVertical center); the press animation scales from the key's own centre; the four arrow hit areas stay large and symmetric. Must look right from iPhone SE to Pro Max widths, with large Dynamic Type, in every remote theme and in RTL. If the owner later leaves a screenshot in a page comment, compare against it.

Done in run 34 (T55): see `src/core/dpadGeometry.ts` and ops/RUNLOG.md.
