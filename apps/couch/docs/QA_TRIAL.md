# QA trial: static review for first Expo Go boot

Static review only (no node_modules, nothing typechecked or bundled). Scope: app/**, src/ui/**,
src/state/**, src/theme/**. Every relative import was checked to resolve to a real file and named
export in src/core, src/ui, src/state and src/theme. No app code imports src/native or src/plus.
All .tsx files parse (bun transpile). `bun test` 127/127, `tsc -p tsconfig.core.json` clean.

## Fixes made in this pass

1. app/_layout.tsx: wrapped the tree in `<SafeAreaProvider>` (expo-router adds one too; nesting is harmless). Settings header now uses theme colours.
2. src/state/session.tsx: `useSyncExternalStore` now gets stable `subscribe`/`getSnapshot` (`useCallback`); before, it resubscribed on every render.
3. src/theme/tokens.ts: `palette()` accepts any string, since newer RN `useColorScheme()` can return `'unspecified'` (would be a type error in `useTheme`).
4. src/ui/keyboard/KeyboardSheet.tsx: the scrim `Pressable` used to wrap the whole sheet, and so did a second `Pressable`. Pressables are `accessible` by default, so VoiceOver/TalkBack saw the whole sheet as one button and could not reach the text field. The scrim is now a sibling behind the sheet. `blurOnSubmit` (deprecated) is now `submitBehavior="submit"`.
5. src/ui/Screen.tsx + src/ui/remote/Touchpad.tsx: added a scroll lock. The touchpad sits inside the page `ScrollView`, and on iOS a vertical swipe would scroll the page and cancel the gesture. Now the touchpad turns scrolling off while a finger is down. Also added `safeTop` so Settings (which has a header) doesn't get a double top inset, plus `keyboardShouldPersistTaps="handled"`.
6. app/(tabs)/apps.tsx: haptics now use the guarded `tap()` helper. Before, `void impactAsync()` could raise an unhandled promise rejection.

## What the owner's first run might hit (most likely first)

1. **SDK vs Expo Go version.** package.json pins SDK 55 (RN 0.83.1, React 19.2). The store build of Expo Go supports only the latest SDK. If that is 56 or newer by now, Expo Go will refuse the project. Fix: `npx expo install expo@latest && npx expo install --fix`. I did not edit package.json (out of scope).
2. **Install peer warnings.** Run `npx expo install --check` after `npm install`. Version ranges were written without registry access, so `react-native-screens ~4.18.0` and `react-native-safe-area-context ~5.6.0` may not be the exact versions SDK 55 expects.
3. **Typed routes.** `.expo/types` doesn't exist until the first `expo start`, so `tsc` before that will complain about hrefs. This doesn't affect the bundle.
4. **config plugin `./plugins/withLanAccess`** is evaluated when `expo start` reads the app config. It requires `expo/config-plugins`, which is fine once `expo` is installed. In Expo Go it has no runtime effect.
5. **Android keyboard sheet.** SDK 54+ is edge-to-edge, and `KeyboardAvoidingView` behavior is `undefined` on Android (it relies on the Modal window's adjustResize). If the keyboard covers the field on Android, try `behavior="height"` on Android.
6. **Android Modal scrim** may not tint the status bar or nav bar (edge-to-edge). This is cosmetic only; `statusBarTranslucent` / `navigationBarTranslucent` could be added.
7. **Touchpad scroll lock** (new) toggles `scrollEnabled` mid-gesture. This is the standard pattern, but verify on a device that a vertical swipe on the touchpad sends UP/DOWN and does not scroll.
8. **Fonts.** If a font fails to load, the app still renders (error path) with system fonts. `fontFamily` names would then fall back silently on iOS but may log warnings.
9. **Glyphs.** Remote glyphs are Unicode text (for example ⌨ and the microphone emoji). They depend on the platform font, and some Android fonts lack ⌨.
10. **app/(tabs)/tvs.tsx** (not reviewed for edits, out of scope) renders `<Link style>` with text children, which is fine. It does not yet offer demo-mode toggles.

## Run 3 review (2026-10-12)

Static review of `git diff 9609489..e1244ac -- app src/ui src/state src/native` against prototype/index.html (v2) and Expo Go safety. Still no node_modules, so no tsc or Metro: every screen was bundle-checked with `bun build` (natives external), which confirms that every relative import resolves. `bun test` passes: 607 tests.

### What was checked

- **Native modules in Expo Go.** Nothing in app/ or src/ statically imports a package that Expo Go lacks. The static native imports are expo-router, expo-haptics, expo-font, expo-splash-screen, expo-status-bar and safe-area-context. AsyncStorage (`src/native/kv.ts`), react-native-udp, react-native-zeroconf and the local modules `modules/lan-wss` and `modules/ir-blaster` are all reached through `require` inside try/catch, and the local modules use `requireOptionalNativeModule`, which returns null in Expo Go and does not throw. `appTransport()` therefore gives fetch only. On boot, `restoreSaved` cannot throw, and with no saved TVs the app falls back to MockTv demo mode.
- **JSON import.** `src/state/lifecycle.tsx` imports `app.json` to read the version. Metro bundles JSON natively, and `expo/tsconfig.base` sets `resolveJsonModule`, so this is fine.
- **Routes.** Every href and router call targets a route that exists: `/remote`, `/apps`, `/tvs`, `/settings`, `/diagnostics`, `/add-tv` and `/add-tv-ir`. `add-tv-ir` and `diagnostics` are registered in the root Stack.
- **Prop contracts.** These all match between components and their callers: VoiceButton `{onNote, onOpenKeyboard}`, SourceSheet `{visible, onClose}`, NumpadSheet `{visible, onClose, onSent?}`, ColorKeys `{onKey}` and AppTile `{app, iconUri, onLaunch, onTogglePin}`. The core APIs the UI calls also exist with the right shapes: `session.can/exec/sendKey/launchApp/activeDriver`, `VoiceController.press/release/cancel`, the inputs.ts helpers, `IconCache.get(driver|null, app)` and every `IrSetupState` step (the switch covers all five).
- **React.** Every list has keys. Hooks are called unconditionally. Effects that subscribe or start async work all clean up: SourceSheet load, apps load and icons, pins, IrSetup subscribe, the lifecycle AppState listener, and VoiceController cancel on unmount.
- **RN props and styles.** All are valid for RN 0.83: `gap`/`rowGap`, `%` widths, `accessibilityRole` alert/radiogroup/none/link, Image `onError`/`resizeMode`, Modal `transparent`/`onRequestClose`, and Pressable `hitSlop`/`delayLongPress`.
- **Accessibility.** Every new button has an `accessibilityLabel`. The colour pills are 30pt tall but have `hitSlop` top/bottom 9 (48pt total).
- **Copy against prototype v2.** The top row (Power/Source/Settings), the D-pad/Touchpad row, Hold to talk, the nav, rocker and mid rows (Mute, 123, Keyboard, Apps), playback, the colour row, Source sheet, Channel number sheet and the IR setup screens (tip, brand question, "find your code", "Code n works") all match.

### Fixed

1. **app/(tabs)/apps.tsx.** Pin toggling wrote to `savedTvStore` from inside a `setState` updater. Updaters must be pure, and StrictMode runs them twice. It now computes the next pins first, then sets state and persists.
2. **app/add-tv-ir.tsx.** `IrSetup` was given `() => names` from the first render, so the default "TV n" name ignored TVs added later. It now reads from a ref that is updated every render.
3. **src/ui/remote/NumpadSheet.tsx.** Two digit taps inside one frame read the same stale `state`. Both keys reached the TV, but the display dropped one. The current display state is now kept in a ref.

### Open risks for the first Expo Go boot (ranked)

1. **SDK and Expo Go version mismatch, and install versions.** These are unchanged from the earlier passes: run `npx expo install --fix`.
2. **Navigation after saving a TV.** Both `add-tv.tsx` and `add-tv-ir.tsx` call `router.back()` and then `router.navigate('/remote')`. Since expo-router v4, `navigate` can push rather than pop, so a modal could stay underneath. On device, check that saving lands on the remote with no modal left behind. If one remains, use `router.dismissTo('/remote')` or `router.dismissAll()`. The IR path stacks a second modal (add-tv, then add-tv-ir), so it is the case most worth checking.
3. **Hold to talk inside the page ScrollView.** A small drag while holding lets the ScrollView take the touch. `onPressOut` then fires and the voice request is sent early. Verify on a device; if it happens, lock scrolling while holding, as the touchpad does.
4. **`expo-modules-core` is not a direct dependency.** `modules/*/index.ts` import it. It is hoisted from `expo`, so Metro resolves it, but `npx expo install --check` may warn.
5. **Diagnostics countdown.** "Retrying in about N s" uses `Date.now()` from the last render and only updates when the reconnect status changes, so it does not count down. This is cosmetic.
6. **Copy drift.** The prototype's Source a11y label is "Source, now X". The app says "Source" because the current input is not known until the sheet loads. The prototype's log line also shows "· vol N", which is omitted because there is no volume readback. Both are minor.

## Premium polish (run 8) — what to watch in the first Expo Go run

Static checks only (bun test 761 green, core tsc clean, every screen bundle-resolves with natives external). Nothing ran on a device. Risks the workers flagged:
1. **react-native-svg** is new (glow, fallback-tile gradient). It ships in Expo Go; `expo install --fix` aligns the `~15.12.1` pin (D12-1). Percentage `rx`/`ry` on ellipses + RadialGradient are standard but unseen on device.
2. **PressableScale** styles its inner Animated.View, not the Pressable: grid/row keys sit in sized wrapper Views. Simple-mode keys in one row may not stretch to equal height when captions wrap.
3. **D-pad arc** uses a rounded View with one coloured border side; **touchpad trail** places dots from the first touch point + drag distance (check for offset).
4. **Rocker hold-to-repeat** relies on Pressable still firing onPress after a long hold (no onLongPress set); a `repeated` guard prevents a double send.
5. **Toast** sits 72 px above the bottom inset (assumes the tab bar fits under it).
6. **Sheets** stay invisible for one frame on first open (measuring height), then spring up; the keyboard sheet keeps the home-indicator padding while the keyboard is up.
7. **Tabs cross-fade** uses bottom-tabs' `animation: 'fade'`; splash fade uses `SplashScreen.setOptions` (guarded).
