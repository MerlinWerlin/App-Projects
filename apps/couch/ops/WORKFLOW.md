# Couch — build run protocol (cloud)

Couch is built by the scheduled task "Couch build" in the cloud, with no PC needed. Each run is a fresh session. All state lives in one place: the **Couch build** artifact
https://claude.ai/artifact/WSdrQqxg2WaFXYDiAjik1b (see `ops/ARTIFACT_URL` for the canonical value)
which holds the status page (`index.html`) and the repo as a base64 git bundle (`repo.bundle.b64.txt`).

The build task is the only writer of this repo. The App Factory overseer may copy the bundle to the PC and ask Codex for reviews, but it never pushes code back. Codex patches come back through the overseer as `.patch` files in the bridge; this protocol applies them in step 3.

## Run steps

1. **Restore.** Artifact `read` the build artifact URL with `path: "repo.bundle.b64.txt"`. Note the artifact version shown in the result (the guard). `base64 -d <saved> > /home/claude/couch.bundle && git clone /home/claude/couch.bundle /home/claude/couch && cd /home/claude/couch && git checkout main`. If the read fails, stop and report "Couch build needs attention: cannot read build artifact".
2. **Lock.** Read `ops/LOCK.json`. If it names another run started under 100 minutes ago, stop quietly with one line "Couch build: another run is active". Otherwise you will publish your own lock only at the end (publishing is atomic via the artifact version guard, so a simultaneous run loses on publish and must stop without retrying).
2-start. **Start marker (D93-1).** Right after restore + lock, before reading oversight, comments or running tests: append `- <date> run N started <UTC time>, oversight v<last seen>` to `ops/RUNLOG.md`, commit, and checkpoint (step 10) at once. Finish the run as usual and then amend that line (replace it with the full entry) before the final checkpoint. A run that dies later still leaves this trace.
2a. **Oversight (before step 3).** Artifact `read` the App Factory Oversight artifact https://claude.ai/artifact/Qe59x61ezQ3sbf7Q61FHAu with `path: "oversight.json"` (read only, never publish to it). Take `apps.tvremote.directives` (agreed by the overseers, Claude and Codex) and `apps.tvremote.patches` (paths on that artifact: read each with Artifact `read` + `path` and save into `ops/inbox/`). Apply open directives as backlog adds/reorders/fixes unless one breaks a hard rule (then reject with a reason). Log every decision in `ops/DECISIONS.md` and store the oversight `version` handled in `ops/status.json` as `oversight_seen`. Skip directives already logged for that id.
2b. **Owner feedback.** ArtifactComments `read` on the build artifact. Each open owner comment becomes a task (or a fix now if small) that outranks the backlog order; reply with what you did and resolve it once done (only threads activated for Claude can be replied to/resolved; list the others in the finish message).
3. **Inbox.** If `ops/inbox/` has `.patch` files (from Codex via the overseer), review each: `git apply --check`, read it, apply if it fits the plan and passes tests, else reject. Record each decision with a reason in `ops/DECISIONS.md` and move the patch to `ops/inbox/done/`.
4. **Green check.** If the npm registry is unreachable (check with a 30 s `npm view expo version`), do not route around it: run `bun test` (Jest-compatible), `tsc -p tsconfig.core.json` and `tsc -p scripts/tsconfig.ui.json` (offline strict check of app/ and src/ui against the stubs in `scripts/tsc-stubs`, oversight D75-1; when an error is a stub gap, add the real API's prop/type to the stub, never loosen own code to fit; `tests/typecheck-ui.test.ts` runs it too), note "full install/typecheck needs PC verification" in RUNLOG and status `next_for_owner`, keep UI code to well-known APIs, and close tasks on that offline evidence (oversight D2-1). T18 closes from the owner's `verify-report.txt` (VERIFY.cmd at the repo root, oversight D65-1): when a page comment carries one, fix every FAILED step first. Otherwise: If `package.json` exists: `npm ci` (or `npm install` when there is no lockfile), then `npm test` and `npx tsc --noEmit`. Fix any red before new work.
5. **Pick work.** From `ops/backlog.json`, take up to 6 tasks with status `todo` (or `in_progress` with a note to continue) whose deps are all `done` or being built in the same wave with a stub contract, in this order: trial blockers, then open owner-comment tasks, then `market-1018` tasks (M2 gaps by demand x cost, M3 redesign T68, M5 screenshots T69), then `polish-1013` tasks, then owner feedback (tasks with `priority: 1` / tags `fb-*`), then lowest id first. Skip tasks that carry a `hold` field (e.g. `"hold": "D6-1"`: an oversight freeze); clear the hold only when the directive that set it is lifted or its condition is met (D6-1: the owner's first trial comment). If none are eligible and tasks remain `todo`, take the blocker; if the only remaining work is held or blocked on the PC (T18), do trial-path hardening only and keep the run short. If the whole backlog is `done`, go to step 9.
6. **Build.** Run the tasks as parallel Agent workers (general-purpose, one task each, each in its own worktree: `isolation: "worktree"`, or when the session's working directory is not the repo, `git worktree add ../wt/<ID> -b task/<ID>` and give the worker that path). Give every worker a common brief (environment facts, owned files, how to test) plus its task's design notes and owned files, so parallel workers never edit the same file. Give each worker: the task JSON, `docs/PLAN.md`, `ops/CONVENTIONS.md`, the rule "own files only, tests + typecheck green, commit on your branch", and "never claim hardware behaviour you could not test; drivers are tested against fixtures". With one task, do it yourself.
7. **Integrate.** Merge branches into `main` one at a time; run the full suite and typecheck after each merge. Revert a merge that turns things red and set that task back to `todo` with a note. Mark merged tasks `done` with the commit hash. Add follow-up tasks you discover (new ids continue the sequence).
8. **Record.** Every run appends a dated entry to `ops/RUNLOG.md`, even a no-op ("no-op: <reason>") or a stop (oversight D79-1: the overseer must be able to tell a hold from a failure); write it before the checkpoint so it ships in the bundle. Append (tasks, commits, test count, issues). Update `ops/status.json` (tests, typecheck, last_run in Sydney time, headline, next_for_owner) and run `python3 ops/render_status.py` to regenerate `index.html` (the status page). Do not hand-edit `index.html`. When a run adds, finishes or re-orders a roadmap phase, update `docs/ROADMAP.md` and tell the librarians: write the same file to the project doc `claude/tvremote-roadmap.md` and add a dated line to the filing log in `claude/INDEX.md` (Projects tool; skill `inform-librarians` when available).
8a. **Trial kit and stage.** `START_TRIAL.cmd` (repo root, CRLF via .gitattributes) checks Node, runs `npm install`, `npx expo install expo@latest` (store Expo Go only opens the latest SDK), `npx expo install --fix`, then `npx expo start --go --tunnel`, teeing install output into `trial-log.txt`; `docs/TRIAL.md` has the owner's steps (Expo Go on iPhone, Node on PC, double-click START_TRIAL.cmd in Desktop\Apps\tvremote\code which the overseer keeps updated, or the page's Download trial kit button; scan the QR; paste trial-log.txt into a page comment if anything is red). `VERIFY.cmd` (CRLF, calls `tools/verify.ps1`, ASCII-only) runs install, expo align, `tsc --noEmit`, `npm test` and `expo export --platform ios` and writes `verify-report.txt`; it ships in the same kit. Each checkpoint also publishes `trial-kit.zip.b64.txt` (`git archive --format=zip HEAD | base64 -w0`) and the status page declares the `downloads` capability. `ops/status.json` tracks `stage`: build → trial (app boots in Expo Go demo mode with the remote working; in the cloud this means code-complete for demo mode, first real boot is the owner's) → owner-tested (owner confirms in a comment) → release-prep (all backlog done). The status page shows the stage under the headline.
9. **Finish line.** When every task in `ops/backlog.json` is `done`, add the release tasks below if they are not already present, and keep working them in later runs. When those are done too: write `docs/RELEASE_CHECKLIST.md` (what the owner must do: Apple/Google accounts, multicast entitlement request, EAS build commands, TestFlight, real-TV test matrix), set the status page headline to "Code complete — ready for real-TV testing", then load `list_triggers`/`update_trigger` via ToolSearch, find the scheduled task "Couch build" and set `enabled: false`. Finish with "Couch build complete: ..." and the owner's next 3 actions.
   - R1 App icon + splash from the brand tokens (original artwork, generic remote motif). (EAS config and the real bundle id `com.jared797.couch` were done by owner-1016 T45.)
   - R2 Demo mode polish for App Review (auto-selected when no TV found; reviewer notes in `docs/STORE.md`)
   - R3 Privacy policy page (`docs/privacy.html`, "Data Not Collected"), support page, non-affiliation line
   - R4 Store listing copy for App Store + Play (title, subtitle, keywords, description, 6 screenshot captions) in `docs/STORE.md`; no brand names in title
   - R5 End-to-end test pass: every screen renders, every control reaches the driver in MockTv, accessibility labels present; fix gaps
10. **Checkpoint.** Update `ops/LOCK.json` to `{"run": "<ISO time>", "state": "idle"}`. `git add -A && git commit` (message ends with the attribution lines below), `git bundle create /home/claude/out.bundle --all`, `base64 -w0 /home/claude/out.bundle > /home/claude/repo.bundle.b64.txt`. Also build the trial kit: `git archive --format=zip -o /home/claude/kit.zip HEAD && base64 -w0 /home/claude/kit.zip > /home/claude/trial-kit.zip.b64.txt`. Publish to the build artifact with `url` = the build artifact URL, `file_path` = the updated `index.html`, `files: {"repo.bundle.b64.txt": "/home/claude/repo.bundle.b64.txt", "trial-kit.zip.b64.txt": "/home/claude/trial-kit.zip.b64.txt"}` (omit `capabilities` once `downloads` is declared, so it carries forward). If the publish is refused because a newer version exists, do not force or retry: write the bundle to the run's summary as lost work and report "Couch build needs attention: version conflict".

Never commit `node_modules`, build output or secrets. Keep the bundle under 10 MB.

## Finish message (every run)
Three lines: tasks done this run (ids), test count + typecheck, what's next — plus the stage. Start with "Couch build needs attention:" if anything blocks (say exactly what the owner should do). The first time the stage becomes trial, start with "Couch is ready to try on your iPhone:" and the steps.
